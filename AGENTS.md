First integrated boot failed before display setup: CircuitPython 10.3.1 lacks `base64`, imported by `overlay_exact_assets.py` through `embedded_icon_library.py`. The subsequent fix makes the Mac build generate `board_icon_index.py` and `board_icons/*.rgba`, and the board icon library loads those raw assets without base64 or zlib. This fix passed desktop tests and build checks but has **not** yet been tried on the S3. Rebuild and copy the entire fresh output, including the new index and directory.

Next board boot hit `SyntaxError` at `totem_runtime.py:1163`: CircuitPython rejects dictionary literal unpacking (`**reference`). Replaced this and the analogous `runtime_io.py` dictionary unpack with `dict.update()`. Desktop suite still passes (47 tests). This second fix awaits an on-device boot.

After loading corrected files, the board got to `TotemRuntime.__init__`, then failed because CircuitPython `random` lacks `shuffle`. The runtime visual modules now import `runtime_random.py`, which provides `shuffle`, `choice`, `uniform`, and seeded `Random` where the board omits them. This compatibility fix passed 47 desktop tests and a staging build; it still awaits a board retry. Rebuild or copy `runtime_random.py` alongside the updated imports.

The first sustained integrated run decoded GIFs, served HTTP and emitted hardware metrics, with ~540–558 KB free RAM and ~0.66 FPS. The runtime had been copying **both** full panel snapshots at two stages on every frame. A hardware-only `snapshot_on_demand` change skips those continuous copies and captures pixels only when a transition starts; desktop rendering retains the distinct stage snapshots. This optimization has desktop tests only; measure new render/FPS and identify whether line artifacts coincide with slideshow transitions or persist on a steady GIF. ## Physical board bring-up: confirmed September 25

- CircuitPython **10.3.1** runs on the user's Adafruit MatrixPortal S3. Two opposite-facing logical **64×32** panels are chained as one 128×32 HUB75 display and powered separately by the 5 V distribution; the board was powered/programmed from Mac USB during tests.
- Both panels showed stable test pixels. The physical panels have **RBG** channel order (requested RGB appeared red/blue/green). Corrected RGB displayed properly on both by swapping green and blue RGB pins in the MatrixPortal setup.
- The custom caller-owned `RGBMatrix(framebuffer=array('H', ...))` path **hard-faulted** at bit depths 3 and 1, even with double buffering off. A direct `memoryview(matrix)` write lit intended and stray pixels, so do not reuse that indexing assumption.
- The verified pixel path is `rgbmatrix.RGBMatrix` with a 128×32, 16-bit `displayio.Bitmap`, `ColorConverter(RGB565)` and `framebufferio.FramebufferDisplay`. After the bitmap canvas was created, CircuitPython reported **2,037,824 free bytes** (2,070,512 before). The user confirmed `matrixportal_bitmap_backend_check.py` **plus the current `matrixportal_backend.py`** showed the red/blue squares cleanly without crashes. That backend now provides the existing runtime's per-pixel interface via a linear Bitmap adapter. Desktop mapping tests also pass.
- `matrixportal_gif_demo.py` played the generated orbit ball and colored-line animations on both panels through one shared GIF decoder. `matrixportal_phone_demo.py` ran a temporary `Festival-Totem-Test` Wi-Fi AP and the phone successfully switched between the two GIFs at the board's `http://<AP-IP>:5000` address. The test HTTP socket must use `recv_into()`, not `recv()`. The phone demo is a limited test controller; it is **not** the polished app.
- `assets/images/` is empty in this checkout. Obtain a small subset of the user's own GIF library before baking actual festival content. The final integrated `code.py`, full phone UI/API, audio source, effects/overlays and performance benchmarks are still outstanding. Keep bit depth at **1** until higher settings are verified on device. Browser microphone capture requires a secure context; the working test page currently uses plain HTTP.

## Goal and current priority

Build a portable, battery-powered festival totem with two opposite-facing HUB75 LED panels, GIFs, graphics/text overlays and transitions, music-reactive visuals, and phone controls that feel like a live instrument. Hardware assembly and travel are imminent. Current priority: finish a reliable physical build, validate the MatrixPortal S3 performance, then refine Vibe/Chaos interaction using real bass-heavy music. The user prefers direct progress and a simple phone UI with safe scrolling.

## Settled decisions

- Two physical **32×64 panels oriented landscape** are logically **64×32 each**, back to back. The MatrixPortal S3 drives them as one chained 128×32 HUB75 output; front and back retain logical identities. Physical back rotation, color order (an RBG quirk was noted), scan compatibility, IN/OUT order, and actual mapping need the real panels and smoke test.
- Front/back can currently be controlled independently or linked. For performance and the physical goal, matching content on both sides is an attractive option, but do not remove independent functionality without checking with the user. Linking control does not automatically imply a single GIF decoder/frame render; measure it.
- Mac/desktop is the authoring environment; CircuitPython MatrixPortal S3 is the target player. GIF crop, fit, positioning, color work, dithering and thumbnails are prepared on the Mac and baked to native 64×32 files. The board should stream prepared media, render lightweight effects/overlays, serve the compiled phone page and accept compact commands. See `MATRIXPORTAL_DEPLOYMENT.md`.
- The phone UI should be safe while scrolling. Active selection uses a small dot beside text. Main navigation is Vibe, Icons, Text, Chaos, Manage; Scenes is a collapsed drawer under the gradient Shuffle button and Previous/Next on Vibe; scene buttons carry distinct colors and icons. Back to GIFs restarts shuffled slideshow. The four starting audio presets Pulse, Spark, Neon, Chaos remain renameable, editable, addable and deletable, with preset buttons in Vibe and their editing controls and sound mapping sliders in Manage → Setup. Audio meters sit below preset choices; input gain, sensitivity and floor reset live in collapsed Input Settings. Signal analyzer remains collapsible. The top mic button starts saved Pulse if no preset was chosen, and Waveform requests the phone mic (HTTPS required). Overlay audio Off/Subtle/Intense applies to both text and icons without changing letter shape. Text dissolves on show, hide, message, size, font and color changes; outgoing text holds its background until its fade completes. Static single/two-line text follows overlay Bounce/Orbit; long text scrolls. Manage → Setup groups background behavior (Black, Dimmed, None), shared icon/static-text Bounce/Orbit, and shared music reactivity under one Overlay Behavior fold; it also owns folded clock/weather settings, set-time editor, editable quick text presets, audio preset management and display controls. GIF Library and Edit / Tags have their own folded groups. Text has colorful one-tap preset buttons; tapping an active icon or text button clears it. Independent, Linked (common starting slideshow with separate rendering), and Mirrored (one rendered image copied to both) are a single three-choice control in the Display & panels fold; Front/Both/Back appears only for Independent. Clock scene background choice is in its Manage settings; slideshow transition controls remain in GIF Library. Browser presets, quick text, and overlay preferences live in phone localStorage, not on the board. Do not reintroduce sample-hit/tap-signal audition controls.
- Phone microphone analysis is the current implemented input: browser Web Audio creates normalized Energy/Low/Body/Bright/Pulse signals and sends compact `audio_frame` messages. It requires the phone browser and mic permission to remain active. Audio analysis is deliberately awaiting tests on a representative bass system; do not assume current calibration is final. The physical I²S microphone is a planned alternate source, not an integrated on-board analyzer yet. Keep the normalized runtime audio interface so either source can drive the visuals.
- Optional joystick/game controller input is a future playability feature, not a prerequisite. An ADS1015 I²C converter was discussed as a way to read an analog joystick while reserving S3 pins for microphone and microSD. Do not assume joystick, ADS1015, microphone, or microSD are already wired or supported by running firmware.
- Wi-Fi phone control and local API are part of the architecture. Future access control or device AP mode is an idea; neither is enabled now.
- Performance should be assessed on **physical hardware**: baseline matrix alone; GIF decoding; mirrored versus independent sides; overlay and transition layers; audio/Chaos; HTTP load; then combinations. Log FPS, free RAM, decode/render/present and HTTP/audio timings, long frame or loop spikes, missed deadlines, voltage/current and battery runtime. No representative hardware benchmark data exists yet.
- Info scenes are distinct from the named Vibe/performance presets: one combined Clock + Weather scene, Set Times, and signal-driven Waveform replace GIF rendering while active. The combined scene defaults to a bright daytime, warm dusk, or dark night sky from approximate time windows (6–8 AM and 6–8 PM are dusk; 8 AM–6 PM is day), regardless of clouds, and a single Black choice overrides the whole scene. The twofold pixel clock reads in 24-hour time with a real colon; temperature and conditions fit beneath it. Selecting the scene syncs clock time and requests current festival weather; if weather fails it displays the last saved or missing reading while the clock continues. The phone sends UTC time plus the America/Chicago offset (including DST); the board keeps time from monotonic ticks, resynced each minute while an information scene is active and the page is open. A cold boot has no trusted time until phone sync. The phone can request current weather from Open-Meteo at the festival venue without GPS, or optionally via phone GPS on a secure browser origin; both require phone internet access. Manual weather entry and last saved weather remain available offline. The browser stores four independent 2026 Wakaan nights and restores them on page load; until official day assignments arrive the official alphabetical roster is an unassigned pick list. A night can hold acts without times; enter times to advance by clock, including sets after midnight (before 9 AM count for the previous night). The schedule is not persisted on the board. The waveform uses normalized Energy/Low/Body/Bright signals. Text and icons share Black, Dimmed GIF (65% brightness), and None backgrounds; audio brightness response is shared while text glyph geometry stays fixed.
- The shared runtime has a selectable mirror mode: render only the front, copy its final pixels to the back, and close the back GIF decoder when supported by the media adapter. This preserves front/back controls for independent mode. Mirroring is selectable in Manage → Setup, not automatically enabled on the physical board; measure it against independent playback before treating savings as verified.

## Power and wiring decision (latest)

The working plan is UGREEN USB-C PD battery → PD trigger → TOBSUN EA50-5V 50 W buck → main fuse → DC switch → 5 V distribution. The two panel power connectors each receive their own parallel 5 V/GND branch. The user has **ordered a 5 V/5 A USB-C male-to-bare-wire power pigtail**, intended as a **third 5 V/GND distribution branch feeding the MatrixPortal S3 USB-C input**. This supersedes the older separate-battery-port controller feed described in previous revisions of `HARDWARE_ARCHITECTURE.md`. Cable rating is capacity, not imposed board current. Verify cable polarity, actual 5 V output, USB-C power-in behavior and branch protection on the bench before final assembly. Use the buck's **output** terminals for all 5 V branches; the PD-trigger side is higher voltage. The buck label says **12 V/24 V input, 5 V 10 A max output**; the trigger offers 5/9/12/15/20 V. Confirm the converter's supported input range and actual PD trigger voltage under load before using 20 V; the photo label alone does not settle intermediate-voltage compatibility. A 5 V/10 A supply may be tight for two bright panels, so cap brightness and measure power. The MatrixPortal's panel mounting terminals are USB-fed **outputs**, not the controller power input. Do not power the controller through HUB75.

The intended parts also include a main fuse (8–10 A was proposed, **not a validated final size**), DC-rated switch and distribution block. A branch fuse suitable for the controller pigtail is desirable because a system fuse sized for panels may not protect a thin branch. Detailed build/testing sequence is in `HARDWARE_ARCHITECTURE.md`.

## Code map

- `simulator.py`: Pygame desktop entry point (64×32 front/back), runs `TotemRuntime` and desktop HTTP controller on port 8765.
- `icon_assets.py` loads PNGs up to 40×40 from `assets/icons/` (nominal 32×32) and up to 72×40 from `assets/icons/large/` (nominal 64×32). Names like `_32x32` do not resize files. The overlay engine centers each canvas without scaling, clips overflow at the 64×32 panel edge, and permits about two pixels of Orbit/Bounce clipping for full-size or oversized artwork. Original exact 32×32 motion remains as before. Desktop Reload Library updates icon names and previews via `/api/icon-previews`; the UI exposes invalid-file errors. `tools/build_large_icons.py` compiles large PNGs into `large_icon_data.py` for PIL-free hardware libraries; `tools/prepare_matrixportal_assets.py` refreshes and includes it in the build. The 60×28 Liquid Stranger asset uses the user's own dripping-letter silhouette with prismatic color inside the exact original transparency mask. This has desktop tests, not device validation; watch icon RAM and frame timing when running on the S3.
- `totem_runtime.py`: owns compact per-side text transition snapshots and a shared overlay duration; the renderer uses a deterministic per-pixel dissolve adapter with no extra full-frame buffer. Icon drawing no longer builds a per-frame pixel list or allocates Random objects for each pixel. Desktop tests cover dissolve endpoints, edit/hide lifecycle and static motion; hardware timing remains unmeasured.
- `totem_runtime.py`: platform-neutral state, phone command routing, two side controllers, slideshow/scene logic and rendering orchestration. `visual_engine.py`, `transition_engine.py`, `text_engine.py`, `overlay_engine.py`, `chaos_engine.py`, `particles.py`, `effects.py`: visual layers and effects.
- `info_scenes.py` draws combined Clock + Weather, Set Times and Waveform without PIL or network requests. `info_scene_ui.py` owns scene controls in Vibe and clock/weather, set-time and combined overlay behavior settings in Manage; `manage_layout_ui.py` folds and groups the assembled Manage cards without cloning their controls; `screen_mode_ui_patch.py` owns the Manage → Setup panel card; `transition_ui_patch.py` owns slideshow background transition labels; `audio_phone_server.py` owns the top microphone button; and `performance_ui_reorg_patch.py` owns navigation and default Pulse startup. The phone stores set times and weather in localStorage and sends compact commands; only its browser fetches Open-Meteo on scene selection or manual refresh. `TotemRuntime.render` uses `TextRenderer.prepare_background` for Dimmed GIF before either icon or text, at 65% GIF brightness. No onboard persistent schedule, automatic weather service, or onboard microphone is implemented.
- `runtime_io.py`: display interfaces and normalized `SignalStore` for phone audio/motion and possible future hardware inputs. Older wire keys `volume/bass/mids/highs/beat` map to the user-facing Energy/Low/Body/Bright/Pulse labels.
- `desktop_media.py`, `image_assets.py` and `image_display.py`: desktop media and authoring. `tools/prepare_matrixportal_assets.py` produces `matrixportal_build/` including manifest, baked GIFs and `www/index.html`.
- `controller_ui.py`: deterministic phone HTML build from `phone_server.PHONE_HTML` and an ordered transform pipeline. `audio_phone_server.py` contains browser analyzer; `performance_phone_server.py` and `performance_ui_reorg_patch.py` shape the Vibe/Chaos controls; the other `*_ui.py` / `*_patch.py` transforms handle layout, text, icons, safe sliders and screen modes. The compiled page is reused for desktop and baked deployment. Changes in the base HTML or transforms can break string anchors; inspect the assembled HTML and its tests.
- `phone_server.py` / `secure_phone_server.py`: desktop controller HTTP. `matrixportal_server.py` and `control_bus.py`: nonblocking CircuitPython HTTP and command queue; the optional access policy is not enabled.
- `matrixportal_backend.py`: single RGB565 128×32 framebuffer with 64×32 logical views and native matrix refresh. `matrixportal_media.py` / `matrixportal_library.py`: separate front/back `gifio.OnDiskGif` players with at most one scheduled decode per loop iteration. `matrixportal_smoke_test.py`: board bring-up and coarse metrics via `runtime_metrics.py`.
- `HARDWARE_ARCHITECTURE.md` and `MATRIXPORTAL_DEPLOYMENT.md`: detailed physical and deployment notes. `tests/`: desktop tests. Code in these modules does **not** establish that a complete CircuitPython app has been deployed.
